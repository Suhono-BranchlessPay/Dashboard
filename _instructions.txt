1. Executive Summary
Survey ini memetakan fitur dashboard control transaksi di 13 platform partner BranchlessPay (OtomaX, Digiflazz, W38s, ST-24, Tiger Engine, Serpul, Payuni, Sipas, Flash Machine, MetroReload, OrderKuota, DigiSwitch, Custom H2H) untuk menentukan apa yang harus BranchlessPay bangun pada dashboard control sisi operator (internal BP) maupun sisi client (B2C user / agent).
Tiga kesimpulan utama:
Posisi BranchlessPay unik. Tidak satu pun kompetitor punya on-chain audit trail, multi-country settlement, atau velocity check terintegrasi. Tiga hal ini harus jadi anchor design dashboard kita.
Gap operasional yang harus segera ditutup. Cash flow rekap harian otomatis, komisi per agen real-time, dan refund/complaint workflow adalah fitur standar industri yang BranchlessPay belum punya. Ini wajib ada sebelum onboarding pilot OtomaX.
Dashboard harus dipecah dua: operator console untuk monitoring 24/7 sisi BP, dan client app/portal untuk agent B2C. Keduanya berbagi data layer yang sama tapi punya UX yang berbeda total.
Rekomendasi roadmap: build dalam 3 fase selama 8 minggu, sinkron dengan pilot OtomaX 30 hari yang Azdi kejar.

3.2 Insight per kompetitor
OtomaX (Windows ┬╖ pasar terbesar)
Anchor utama: Addon Rekapan dengan formula keuangan otomatis (Saldo Awal ΓêÆ Transaksi + Cash + Komisi + Tiket + Non-Tiket = X; X ΓêÆ Saldo Akhir = Selisih). Jika selisih tidak nol, sistem auto-flag. Bank mutation matching per bank per operator (claimed/unclaimed) adalah fitur tidak ada di kompetitor lain. UI berbasis web, bisa diakses dari PC dan smartphone, tapi tidak mobile-first.
Pelajaran untuk BranchlessPay: formula rekap harian dan flagging selisih ini wajib kita port ke dashboard operator. Bank matching adalah fitur premium yang bisa kita charge.
Digiflazz (marketplace H2H)
Anchor utama: webhook + cek status sinkron, fitur Lapor Tidak Valid / Laporan Selesai langsung dari UI. Transaksi tercatat realtime dan downloadable dalam berbagai format untuk tim keuangan. Tidak ada cash flow rekap karena Digiflazz hanya marketplace, bukan platform pengelolaan dana sendiri.
Pelajaran untuk BranchlessPay: workflow complaint dengan satu tombol (lapor / selesai) adalah UX standar yang user agent harapkan. Kita harus punya equivalent di mobile app.
Tiger Engine (high volume queue)
Anchor utama: queue-based architecture dengan Bull, rate limit dan retry policy per supplier. Dashboard menonjolkan throughput dan latency per partner. Cocok untuk reseller dengan volume >10rb trx/hari.
Pelajaran untuk BranchlessPay: tampilan partner health (P99 latency, error rate, status circle hijau/kuning/merah) adalah pola UX yang harus kita adopsi. Operator perlu lihat dengan satu glance partner mana yang sedang issue.
DFAsist (third-party Digiflazz)
Bukan partner langsung tapi ekosistem Digiflazz, dijual Rp 4 juta/bulan. Memantau produk gangguan, update harga, dan handle pending transaction otomatis. Filter whitelist/blacklist seller, product code rules (mis. blacklist kode MLSLOW* dari seller A meskipun lebih murah).
Pelajaran untuk BranchlessPay: ini sinyal kuat bahwa partner B2B mau bayar mahal untuk monitoring otomatis. Layer monitoring proaktif (alerts via WhatsApp/Telegram, auto-disable produk gangguan) bisa jadi differentiator BranchlessPay.
W38s, ST-24, Sipas, Flash Machine, MetroReload, OrderKuota, DigiSwitch, Payuni, Custom H2H
Sembilan platform ini bervariasi dari open source PHP (W38s) sampai institusi (Sipas: sekolah/pesantren/koperasi). Common pattern: punya panel admin web standar, integrasi via HTTP/JSON callback, jarang punya mobile-first UI. Komisi per agen tier ada di sebagian besar tapi cash flow rekap dan bank matching hampir tidak ada di luar OtomaX.
4. Gap Analysis BranchlessPay Saat Ini
4.1 Yang sudah ada
Dari user memories dan observasi dashboard partner portal:
Live transaction feed melalui endpoint /api/partner/v1/settle dengan webhook ke URL partner
Settlement status flow lengkap: INITIATED ΓåÆ CONFIRMED ΓåÆ RECONCILED, dengan history transition
Webhook configurable + secret (HMAC-SHA256), retry policy 4x dengan backoff
On-chain audit trail di Monad testnet (tx_hash per transaksi), dipertahankan immutable
Velocity check + geo-fencing + audit logs sudah di backend
Agent tier system 1/2/3 tersedia di smart contract AgentRegistry
Multi-country region selector (9 negara) dan i18n React 18 dengan deteksi browser
Mobile app Android offline-first (WatermelonDB outbox), biometric auth, push notifications
4.2 Yang belum ada (gap yang harus ditutup)
Berdasarkan benchmark, prioritas dari paling kritis:
Tier 1 ΓÇö Wajib sebelum pilot OtomaX (4 minggu)
Cash flow rekap harian otomatis untuk operator: total volume in/out, fee earned, success rate per jam
Komisi & profit per agen real-time: agent dashboard yang tampilkan earnings hari ini, minggu ini, bulan ini
Refund & complaint workflow: dua tombol di mobile app (Lapor Tidak Valid / Tandai Selesai) yang trigger workflow ticket di sisi operator
Alerts & anomaly feed di operator console: velocity breach, latency spike, geo-fencing flag, failed Monad write
Partner health monitor: status circle (hijau/kuning/merah) per partner dengan P99 latency, error rate 5 menit terakhir

Tier 3 ΓÇö Q3-Q4 2026
Rule engine per country (compliance differ per negara)

AI Agents ΓÇö tunggu data trial real dulu (sesuai roadmap)
5. Spesifikasi Dashboard BranchlessPay
Pisah dua produk: Operator Console (internal BP) dan Client Portal/App (agent B2C). Mockup terlampir terpisah.
5.1 Operator Console ΓÇö sisi BranchlessPay
Target user: tim ops BranchlessPay (saat ini Malik solo, post-investment akan jadi tim 3-5 orang) dan investor view untuk Anthropic/VC. Akses via web app, desktop-first (1440px+), tapi tetap responsive sampai 768px.
5.1.1 Top-level layout
Top bar: logo BP, environment toggle (PROD/SANDBOX/TESTNET), region filter (ID/PH/VN/MX/dst), Monad RPC status indicator, notification bell, user menu
Metric cards row (4 cards): Transaksi hari ini, Settlement Volume, Success Rate, Active Agents ΓÇö semua dengan delta vs kemarin
Two-column main area: live transaction feed (60%) + sidebar partner health & Monad audit trail (40%)
Bottom row: volume by country breakdown + alerts & anomalies feed
5.1.2 Live transaction feed
Real-time stream dengan auto-refresh setiap 2 detik. Kolom: Ref ID, Agent, Product Code, Amount, Status (INITIATED/PENDING/CONFIRMED/FAILED). Filter: by agent, by status, by transaction_type, by partner. Click row ΓåÆ drawer dengan history transition lengkap + tx_hash + webhook attempts.
5.1.3 Partner health monitor
Card list 13 partner. Per partner: circle status (hijau <500ms, kuning 500-1500ms, merah >1500ms / timeout), P99 latency 5 menit terakhir, error rate, throughput. Click partner ΓåÆ detail panel: response time histogram 24 jam, failure breakdown by error_code, last 50 webhook deliveries.
5.1.4 Monad audit trail card
Live feed 3 tx_hash terbaru dengan block number dan timestamp. Click hash ΓåÆ buka Monad explorer di tab baru. Counter: total fees recorded today, total fees this month, blockchain confirmation rate.
5.1.5 Alerts & anomalies
3 prioritas warna: red (critical, ops langsung action), yellow (warning, ops monitor), blue (info, log saja). Setiap alert click-through ke transaksi/agent/partner terkait. Integrasi: kirim ke Slack #ops-alerts dan WhatsApp grup Malik+Joni untuk red alerts.
5.2 Client Portal / Mobile App ΓÇö sisi user agent B2C
Target user: agent Tier 1/2/3 di Indonesia (lalu PH, VN). Mobile-first (Android dulu, iOS Q3). Web portal sebagai fallback untuk laptop.
5.2.1 Layout mobile app
Header: greeting + nama agent, badge tier (Tier 1/2/3 Mitra), agent ID
Balance card hero: saldo wallet dengan 3 tombol primary (Topup, Tarik, Riwayat)
Quick action grid 4x2: Pulsa, PLN, Data, Game, SPP, PDAM, BPJS, Lainnya ΓÇö icon Tabler outline, label pendek
Latest transactions (3 row): produk, recipient masked, amount, status badge
Bottom navigation: Home, Transaksi, Performa, Akun
5.2.2 Receipt blockchain
Halaman detail transaksi yang dibedakan dari aplikasi server pulsa lain: section khusus Monad Audit Trail yang menampilkan tx_hash, block number, timestamp on-chain, dengan tombol Verifikasi yang buka explorer. Ini selling point untuk meyakinkan agent bahwa transaksinya immutable dan bisa diverifikasi siapapun.
5.2.3 Performa 30 hari
3 metric cards: total trx, volume, komisi. Sparkline trend 30 hari. Breakdown per kategori produk. Untuk tier 3, tambah leaderboard nasional anonim (You are top 12% dari semua agent di Indonesia).
5.2.4 Tier progression
Progress bar visual menuju tier berikutnya. Tampilkan requirement (trx count, saldo rata-rata, durasi aktif) dan benefit per tier. Gamifikasi ringan: konfeti animation saat naik tier, badge collectible.
5.2.5 Refund & complaint flow
Di detail transaksi yang status SUCCESS tapi user complaint: tombol Lapor Tidak Valid ΓåÆ form (kategori issue, deskripsi, attach screenshot). Workflow: notify ops via Slack, status berubah ke UNDER_REVIEW, ops investigate, response via push notification + dalam app. Tombol Tandai Selesai jika ternyata transaksi valid.

7. Technical Considerations
7.1 Stack alignment dengan yang ada
Frontend operator console: React + TypeScript + Tailwind (sama dengan portal admin sekarang)
Frontend B2C web: Next.js dengan react-i18next (sesuai standing instruction multi-language)
Mobile app: existing Expo + WatermelonDB offline-first stack
Backend: Node.js + PostgreSQL + Redis (existing) + tambahan ClickHouse untuk metric aggregation high-volume
Real-time: SSE (Server-Sent Events) untuk live feed, lebih ringan dari WebSocket untuk one-way data
Charts: Recharts (sudah dipakai), atau plotly untuk visualisasi advanced
7.2 Performance budget
Operator console first paint < 1.5s pada 3G
Live feed lag < 3s dari trx terjadi ke tampil di UI
Mobile app cold start < 2s, hot start < 500ms
Bundle size mobile app < 8MB (target Play Store best practice)
7.3 Security & compliance
Operator console: JWT + 2FA wajib untuk semua user internal BP
Audit log setiap action operator (siapa lihat data agent X, siapa trigger refund)
PII masking di operator console untuk role non-admin (phone & email blur kecuali admin level)
Mobile app: biometric re-auth setiap kali buka detail transaksi dengan amount > Rp 1jt
Rate limit operator API: 100 req/min per user untuk prevent scraping

8.2 Definisi metrik dashboard
Success rate = COUNT(status=CONFIRMED) / COUNT(all trx) dalam window 1 jam
P99 latency partner = persentil ke-99 dari (timestamp_response ΓêÆ timestamp_request) per partner, sliding window 5 menit

Settlement volume = SUM(amount_idr) per environment, exclude failed
